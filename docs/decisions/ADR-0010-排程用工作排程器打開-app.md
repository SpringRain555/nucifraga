# ADR-0010：排程用 Windows 工作排程器打開 app，備份在畫面上跑

**狀態**：已採用
**日期**：2026-10-24

## 背景

M3 要有「定時備份」。維護者的備份碟是**離線外接碟**，平常沒接上；排程時間到時碟多半不在。
使用者 2026-10-24 決定：碟沒接上時**在畫面上提醒**、接上後按「繼續」再偵測，**不用 Windows 通知**。

## 決定

- **工作排程器在指定時間執行 `nucifraga-app.exe --run "<模板>"`**，不是在背景跑 CLI。
  app 已經開著時，第二個行程把參數交給第一個（單一實例）後結束；第一個把畫面帶到執行中並開始備份
- 碟沒接上 → `AwaitingDestination`（state-machines §1）：畫面停下來等「已接上，繼續」，不是失敗
- **排程設定存在模板裡**（`nucifraga.schedule`：`time` 與 `days`），工作排程器裡的工作是它的投影：
  - app 每次啟動、換模板資料夾之後，依看得到的模板重建 `\nucifraga\` 底下的工作，對不到模板的移除
  - 工作名稱是模板路徑（小寫）的 SHA-256 前 12 碼，所以同一份模板永遠對到同一個工作
  - 模板資料夾換到新電腦時，排程跟著過去；第一次開 app 就會在新電腦上建好
- 工作的設定：登入中的使用者、一般權限（要開得出視窗）；錯過的開機後補跑（`StartWhenAvailable`）；
  用電池也跑；不限執行時間；已經在跑就不再開一個
- 用 `schtasks.exe /Create /XML`（UTF-16 的 XML 暫存檔，用完刪掉那一個檔案），不寫 COM 介面 —— 不需要新的 unsafe

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| 背景跑 CLI，不開視窗 | 碟沒接上時沒有人可以問，只能失敗；使用者要的是「在畫面上提醒、接上後繼續」 |
| app 常駐系統匣、自己計時 | 違反「關掉視窗就是結束」（app-lifecycle 第 4 題）；電腦睡眠、重開機都要自己處理，工作排程器已經做好了 |
| 排程存在 app 的 `settings.json` | 跟模板分家：模板搬家或換電腦時排程不見；而且是第二份要同步的事實 |
| Windows 通知提醒接碟 | 使用者明確不要 |

## 代價

- 每次啟動都跑幾次 `schtasks`（在背景執行緒，不擋視窗）
- `schtasks` 的錯誤訊息是系統語系編碼，`APP-007` 裡的細節可能是亂碼；離開碼一定看得到
- app 的 exe 搬家（重新安裝到別處）後，工作在下一次開 app 時才會指到新位置

## 什麼情況要重新考慮

- 支援 Windows 以外的平台（那時改用各平台的排程機制，介面不變）
- 使用者要「無人值守、碟一直接著」的伺服器式用法：那時加一個「背景跑、不開視窗」的選項，走 CLI

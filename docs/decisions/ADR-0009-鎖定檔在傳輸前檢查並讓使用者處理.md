# ADR-0009：被佔用的檔案在傳輸前檢查，列出佔用程式讓使用者處理

**狀態**：已採用
**日期**：2026-10-23

## 背景

使用者要求：「開始備份前先提示哪些檔案需要處理（關閉）」（2026-10-23）。
被其他程式開著的檔案（Outlook 的 `.pst`、執行中的 SQLite、虛擬機磁碟）常常無法以共用讀取開啟；
現行的檔案總管做法會跳錯誤對話框，一次一個。

Windows 的 Restart Manager 是給安裝程式用的：它能查出某個檔案正被哪些程式與服務使用
（來源見 market-scan）。

## 決定

- 在**比對之後、傳輸之前**多一個 `CheckingLocks` 狀態：**只對計畫裡要讀的檔案**以共用讀取試開
- 打不開的，用 Restart Manager（`RmStartSession` → `RmRegisterResources` → `RmGetList`）查佔用的程式名稱
- UI 依程式分組：「Outlook（3 個檔案）」，三個選項 —— 我關好了，重新檢查／略過這些檔案／取消這次備份
- 模板的 `alwaysSkipLocked` 可以列出「本來就一直開著」的檔案樣式，符合的不問、直接略過並記 `SRC-003`
- 檢查之後才被鎖住的檔案，傳輸時記 `SRC-004` 並略過，不中斷整次執行
- **只查不關**：nucifraga 不幫使用者關閉任何程式（Restart Manager 有這個能力，我們刻意不用）
- 這個功能在 `cfg(windows)` 底下；其他平台跳過這一步

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| VSS 陰影複製（開著的檔案也備份得到） | 每次都要系統管理員權限（UAC 視窗）、只有 Windows 有；可以之後再加 |
| 對所有來源檔案都先試開一次 | 數十萬檔時太慢；要讀的只有有變的那一小部分 |
| 自動關閉佔用的程式 | 會讓使用者的工作消失；備份工具不該有這種副作用 |

## 代價

- 檢查與傳輸之間有時間差，檢查通過的檔案仍可能在傳輸時被鎖（所以 `SRC-004` 仍然存在）
- 要寫 Windows API 綁定（`windows` crate 的 `Win32_System_RestartManager`）

## 什麼情況要重新考慮

- 使用者常態性需要備份「一直開著」的檔案（例如每天都開著的資料庫）：那時評估 VSS

# ADR-0004：備份碟用「單一鏡像＋舊版本資料夾」，不再每次全量快照

**狀態**：已採用
**日期**：2026-10-23

## 背景

現行做法（`D:\_meta\CONVENTIONS.md` §4.2）是每次在備份碟建一個 `<yyyyMMdd>_backup\`，整份複製過去。
備份碟是 **exFAT**：它不支援硬連結（硬連結是 NTFS 的功能，來源見 market-scan），所以沒辦法像
rsync `--link-dest` 那樣讓沒變的檔案在每份快照之間共用。結果是：

- 每次都要讀寫全部的資料，時間跟總量成正比，資料越多越慢（需求 5）
- 每份快照都完整佔一份空間

## 決定

- `current\<來源名>\` 是**唯一一份鏡像**：每次只寫有變的檔案
- 被覆蓋或被刪除的舊檔**搬到** `_versions\<yyyyMMdd-HHmm>\<來源名>\`，保留原本的資料夾結構
  （這與 FreeFileSync 的「Versioning」概念相同；我們沒有複製它的程式碼或命名規則）
- 舊版本**預設永久保留**，只有使用者在 UI 上手動刪（使用者 2026-10-23 決定）
- 已經存在的 `<yyyyMMdd>_backup\` 原樣保留，nucifraga 不讀、不改、不刪

版面細節與路徑預算在 `docs/architecture/storage-layout.md`。

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| 維持每次全量快照 | exFAT 沒有硬連結，時間與空間都隨總量成長 |
| 兩種都給，模板選 | 多一條要測試與寫文件的路徑；全量快照的唯一優點（每份獨立）用「舊版本＋報告」已經大致涵蓋 |
| 舊版本放在檔名後綴（`a.txt.20261023`） | 會跟正式檔案混在一起；刪舊版本也得逐檔找 |

## 代價

- 備份碟的版面跟現在不同：`D:\_meta\CONVENTIONS.md` §4.2 要改寫，`Test-BackupPaths.ps1` 的前綴算法只適用於舊做法
- 舊版本那一層的路徑前綴比舊做法長 8 字元（資料夾預算 195 → 187）；鏡像那一層反而短 8 字元
- 想看「某一天整份長什麼樣」做不到（要把 `current` 加回那天之後的舊版本才拼得出來）；要靠 M3 的還原功能

## 什麼情況要重新考慮

- 目的地改成 NTFS 或支援硬連結／reflink 的檔案系統，而且使用者確實需要「某一天的完整樣子」

# ADR-0011：還原預設放到新資料夾，任何情況都不覆蓋現有的檔案

**狀態**：已採用
**日期**：2026-10-24

## 背景

M3 要有「還原畫面」：從備份碟的「目前版本」（`current\`）或某個舊版本時間點（`_versions\<時間>\`），
把選的檔案拿回來。還原是**寫進使用者的資料夾**的動作：寫錯地方、蓋掉現在的檔案，就是用備份工具弄丟資料。
使用者 2026-10-24 決定：預設放到新資料夾。

## 決定

- **預設還原到新資料夾**：在使用者選的位置（預設桌面）建「nucifraga 還原 <時間>」，底下保留「來源名＼原本的相對路徑」。
  同名的資料夾已經存在就加「 (2)」，所以一定是全新的資料夾
- **可以選「放回原位」**：依模板裡的來源對應回各來源資料夾。原位已經有同名檔案的，**先列出來**，讓使用者選
  「略過這些，保留現有的」或「兩份都留：還原的那份存成『名稱 (還原)』」。**沒有「覆蓋」這個選項**
- 每個檔案都用 `create_new` 開（已經存在就失敗）：就算「檢查存在」與「寫入」之間別的程式剛好存了同名檔，也不會被蓋掉
- 寫完從同一個 handle 讀回比對 SHA-256，不符就刪掉**這次自己建的那一個檔案**、報 `RST-003`；設回原本的修改時間
- **備份碟只讀**；不能還原到備份碟裡面（`RST-004`）；備份進行中不能還原（備份會在途中搬動 `current\` 的檔案）
- 畫面送來的相對路徑只能往下走（不可有 `..`、磁碟代號），時間點名稱要符合格式

## 考慮過但沒選的

| 方案 | 為什麼不選 |
|---|---|
| 放回原位並覆蓋（像檔案總管的「取代」） | 還原最常見的情境是「改壞了」，但使用者不一定記得原位現在那份是不是也想留；一次錯就是第二次弄丟 |
| 覆蓋前把現有的搬到資源回收筒 | 要多一條寫入使用者資料夾之外的路徑；而「兩份都留」已經涵蓋需要 |
| 用檔案總管開時間點資料夾、讓使用者自己複製（M1 的做法） | 檔案總管遇到長路徑會漏（lessons 第一條）；不驗雜湊 |

## 代價

- 「兩份都留」之後，使用者要自己決定留哪一份
- 還原大量檔案到新資料夾時佔兩倍空間（原位那份仍在）

## 什麼情況要重新考慮

- 使用者明確要求「整個資料夾回到某個時間點」（那需要刪掉之後才新增的檔案，是另一件事，要另外設計）

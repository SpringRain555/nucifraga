# 目的地版面

**這一份是「備份碟上會出現哪些資料夾、每個是什麼、誰可以刪」的權威。**
決策理由在 [ADR-0004](../decisions/ADR-0004-單一鏡像加舊版本資料夾.md)。

## 版面

```
<目的地根>\
├─ .nucifraga\
│  ├─ destination.json        目的地標記：這顆碟是哪一個目的地（id、建立時間、版面版本）
│  ├─ catalog.sqlite          目錄：每個已備份檔案的來源大小／mtime／雜湊（可重建的快取）
│  └─ run.lock                執行鎖：同一個目的地同時只能有一次執行
├─ current\<來源名>\…          鏡像：每個來源「目前」的樣子，檔案總管可以直接打開
├─ _versions\<yyyyMMdd-HHmm>\<來源名>\…
│                              舊版本：那一次執行裡被覆蓋或被刪除的檔案，保留原本的資料夾結構
└─ _reports\<yyyyMMdd-HHmm>\
   ├─ summary.txt             給人看的摘要（繁體中文）
   ├─ report.json             給程式看的完整報告（每個錯誤、每個略過的檔案）
   └─ manifest.jsonl          這一次寫入或確認過的每個檔案：路徑、大小、SHA-256
```

- **`<來源名>`** 預設是來源資料夾的最後一段（`D:\Projects` → `Projects`）。兩個來源撞名時，
  模板要用 `name` 欄位取別名，否則預檢報 `CFG-006`。手機來源是 `phone-<裝置名>`（M2）。
- **時間戳記用本機時間、精確到分鐘。** 同一分鐘內第二次執行會加 `-2`、`-3`。
- **`<yyyyMMdd>_backup\`**（舊做法的全量快照）如果已經在目的地根，**原樣保留、只讀、不轉換**。
  nucifraga 不讀它、不刪它、不把它算進任何統計。

## 誰可以刪什麼

| 東西 | 會被誰刪 | 條件 |
|---|---|---|
| `current\` 底下的檔案 | **不會被刪。** 來源刪了或改了，舊檔是被**搬**到 `_versions\` | — |
| `current\` 底下的 `*.nucifraga-tmp` | engine | 自己這一次或上一次中斷留下的暫存檔；名稱必須完全符合格式 |
| `_versions\<時間>\` | **只有使用者**，在「舊版本」畫面按刪除 | 預設永久保留（模板的 `versioning.retentionDays` 預設 `null`）；刪之前列出路徑、檔案數、大小 |
| `_reports\` | 不刪 | 很小，留著當紀錄 |
| `.nucifraga\catalog.sqlite` | core（重建時） | 開不起來或版本不符時改名成 `catalog.broken-<時間>.sqlite` 再重建，**不直接刪** |

所有刪除都走 `core::safe_delete`，它在動手之前斷言三件事：

1. 路徑在目的地根之下（正規化之後比對，擋 `..` 與 junction）
2. 目的地根有 `.nucifraga\destination.json`，而且 id 與模板記錄的一致
3. 目標的名稱符合預期格式（`_versions` 底下是 `yyyyMMdd-HHmm(-n)?`，暫存檔是 `*.nucifraga-tmp`）

三件任何一件不成立就拒絕並回 `ENG-010`。**刪除的路徑永遠不是由字串拼出來就直接用** ——
這條規則的來由見 [lessons](../lessons.md)「遞迴刪除的路徑由變數拼出」。

## 路徑預算

目的地的路徑比來源長，差多少由版面決定。以範例目的地根 `E:\01_data-backup_<機器>`（38 字元）
與來源 `D:\Projects`（11 字元）為例：

| 位置 | 前綴 | 前綴差 | 資料夾預算（≤ 247 − 差） | 檔案預算（≤ 259 − 差） |
|---|---|---:|---:|---:|
| 舊做法 `<yyyyMMdd>_backup\Projects` | 63 | 52 | 195 | 207 |
| 鏡像 `current\Projects` | 55 | 44 | 203 | 215 |
| 舊版本 `_versions\yyyyMMdd-HHmm\Projects` | 71 | 60 | 187 | 199 |

（同一分鐘第二次執行的 `-2` 後綴再多 2 字元；預檢按實際名稱算，不按這張表。）

**nucifraga 自己寫檔一律用 `\\?\` 長路徑**，所以超過 260 的檔案**照樣寫得進去，不會漏**
（Windows 長路徑規則見 `docs/research/market-scan.md` 的來源）。預算之所以還要檢查，是因為
**使用者之後可能用檔案總管把檔案拖回來** —— 那時候檔案總管的限制又回來了。所以：

- 超過資料夾預算 → `PATH-001`（警告）：備份得到，但用檔案總管還原那一層會失敗
- 超過檔案預算 → `PATH-002`（警告）：同上，但檔案總管通常仍複製得過去，嚴格遵守 MAX_PATH 的工具會失敗
- 單一名稱超過 255 → `PATH-003`（錯誤）：檔案系統本身存不了，這個檔案略過

預檢用**這一次真正會用到的最長前綴**計算（有要搬到 `_versions` 的檔案才用舊版本那一列）。
模板可以把 `pathPolicy` 設成 `block`，讓 `PATH-001` 變成擋下整次執行的錯誤。

## 檔案系統

| 目的地檔案系統 | 支援 | 備註 |
|---|---|---|
| NTFS | ✅ | — |
| exFAT | ✅ | 沒有日誌：拔除前要「安全移除」；不存 symlink／硬連結（來源的 reparse point 一律略過並列出，見 `SRC-006`） |
| FAT32 | ⚠️ | 單檔上限 4 GiB：預檢時找出超過的檔案，報 `DST-006` 並略過那些檔案 |
| 網路磁碟（SMB） | ⚠️ M1 不測 | 可以選，但不在驗收範圍 |

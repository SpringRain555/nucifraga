# REQ-0007：資料量增加，備份不會跟著變慢

**狀態**：已確認
**日期**：2026-10-23

## 使用者要什麼

這是要長期用的工具。資料越存越多之後，每次備份的時間應該跟「這次改了多少」有關，而不是跟「總共有多少」有關。

## 驗收條件

- [ ] 第二次以後的執行只讀取大小或修改時間有變的檔案
- [ ] 基準：合成 50 萬個小檔、沒有任何變更時，第二次執行（預檢＋掃描＋比對）在 SSD 上 ≤ 60 秒；結果寫進 `docs/operations/benchmarks.md`
- [ ] 索引（catalog）損毀時自動重建，結果正確（只是那一次比較慢）
- [ ] 執行中的記憶體用量不隨檔案數線性成長到無上限：50 萬檔時 ≤ 1 GB

## 刻意不做

- 檔案內容層級的差異傳輸（只傳改過的區塊）
